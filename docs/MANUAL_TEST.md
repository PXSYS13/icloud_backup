# Ручная проверка на настоящем Apple ID

Короткий чек-лист для автора: что проверить на реальном аккаунте перед релизом. Демо-движок (`uv run webui.py --demo`) проходит весь путь сам, но настоящий iCloud он не заменяет: вход, коды, список и ссылки на скачивание проверяются только здесь. Пометки в квадратных скобках — что ожидается.

## Перед началом

- [ ] На айфоне выключена «Расширенная защита данных» и включён доступ к данным iCloud в интернете (iOS до 26.3: «Настройки» → имя → iCloud → «Доступ к данным iCloud в интернете»; iOS 26.4 и новее: … → iCloud → iCloud.com → «Разрешить доступ к данным»). Подождали пару минут.
- [ ] Распакован свежий ZIP в отдельную папку, в ней нет `.env`, `session/` и `state.db` от прошлых попыток.
- [ ] Записано, сколько фото и видео показывает приложение «Фото» на айфоне (Медиатека → внизу «N фото, M видео») — для сверки.

## Запуск

- [ ] Двойной клик по `webui.bat` (Windows). [Чёрное окно, при первом запуске установка uv и Python, потом браузер открыл `localhost:8000`.] Если SmartScreen — «Подробнее» → «Выполнить в любом случае».
- [ ] На macOS: двойной клик по `webui.command` (если Gatekeeper не пускает — правой кнопкой → «Открыть»). На Linux: `bash webui.sh`. [На машине без uv скрипт ставит его через официальный `install.sh`, потом ставит Python и зависимости и открывает браузер; при повторном запуске ничего не ставит.]
- [ ] Закрыть чёрное окно и запустить снова. [Открылась та же страница; состояние не потерялось.]

## Подготовка и вход

- [ ] Главная → «Подготовить айфон» → отметить пункты → «Всё готово — войти». [Экран «Вход».]
- [ ] Ввести Apple ID и заведомо неверный пароль. [Красное сообщение «Apple не принял Apple ID или пароль…», форма осталась.]
- [ ] Ввести верный пароль. [На айфоне пришёл код; в программе появилось поле «Шесть цифр с айфона». Если на айфоне спросили «Разрешить вход?» — «Разрешить».]
- [ ] Ввести неверный код. [«Код не подошёл…», поле осталось.]
- [ ] Ввести верный код. [«Вы вошли. Сессия сохранена», главная; слева «Apple ID: iv…n@icloud.com» (логин замаскирован).]
- [ ] Открыть папку `session/` рядом с программой. [Есть `account.json`, файл cookies и `<appleid>.session`; пароля нигде нет.]
- [ ] Открыть `logs/webui.log`. [Нет пароля, кода и полного Apple ID.]
- [ ] Закрыть чёрное окно, запустить снова. [Вход не потребовался: слева снова «Apple ID: …».]

## Медиатека

- [ ] «Проверить медиатеку». [Кольцо «получаю список», счётчик найденных растёт; в конце «В iCloud N файлов», карточка «Медиатека iCloud» с фото, Live Photo, видео и таблицей по годам.] Сверить общее число с приложением «Фото» (Live Photo считается одним файлом; «Недавно удалённые» и скрытые не считаются).
- [ ] Посмотреть «Свободно» и, если места меньше размера медиатеки, увидеть баннер «Места на диске может не хватить». Сменить папку на другой диск: «Папка для фото» → «Сменить папку». [Корень диска `D:\` отклоняется с объяснением; обычная папка принимается.]

## Скачивание

- [ ] «Скачать всё». [«Идёт скачивание», растут «Скачано» и скорость, видна текущая строка с именем файла, справа «Последние скачанные».]
- [ ] Открыть папку. [Файлы лежат в `ГГГГ/ГГГГ-ММ/`, у Live Photo рядом `.HEIC` (или `.JPG`) и `.MOV` с тем же именем; дата изменения файла — дата съёмки.]
- [ ] «Пауза» → подождать → «Продолжить». [Скачивание продолжилось, числа не откатились.]
- [ ] «Остановить» → подтвердить → закрыть чёрное окно → запустить снова → «Продолжить». [Начало с того же места: «Скачано» не обнулилось; в папке нет лишних копий; `.part`-файлы исчезли по мере докачки.]
- [ ] Выключить Wi-Fi на минуту во время скачивания. [Пилюля «Жду Apple», в ленте «… Повтор через N с»; после включения Wi-Fi скачивание продолжилось само.]
- [ ] Во время остановки посмотреть размер какого-нибудь `.part` в папке, потом «Продолжить». [Файл дорос с прежнего размера, а не начался с нуля (видно по скорости и по тому, что размер не обнулился).]
- [ ] Имитация истёкшей сессии: во время скачивания удалить файлы cookies из `session/` (не `account.json`) и подождать. [Пилюля «Нужно войти снова», баннер «Сессия Apple истекла» с кнопкой «Войти снова»; после входа «Продолжить» докачивает с того же места.] Если Apple не выдаёт ошибку сразу, этот пункт можно пропустить.
- [ ] На втором аккаунте (или после включения «Расширенной защиты данных») войти и нажать «Проверить медиатеку». [Сообщение про ACCESS_DENIED с путями к настройкам айфона; после исправления настроек и повторного входа всё работает.]
- [ ] Дождаться конца. [Автоматически открылся экран «Готово: спасено N фото и M видео (X ГБ)» с путём к папке и кнопкой «Поддержать проект»; числа сходятся с содержимым папки; кнопки «Поддержать проект», «Telegram-канал» и «Яндекс БК» ведут на нужные адреса.]
- [ ] Отдельный прогон без предварительной проверки: «Сразу скачать всё». [Сначала собирается список, потом идёт скачивание — без лишних вопросов.]
- [ ] Выборочно открыть несколько фото и видео из разных лет. [Открываются, это оригиналы, не превью.]
- [ ] Если что-то «не скачалось»: на главной «Повторить для N файлов». [Файлы вернулись в очередь и докачались или снова попали в «не скачались» с причиной в журнале.]

## Обработка

- [ ] «Обработка» → формат «Оба» → «Сделать JPG-копии сейчас». [Рядом с каждым HEIC появился JPG; в свойствах JPG — дата съёмки и геометка (Windows: «Подробно» в свойствах файла); HEIC на месте.]
- [ ] Формат «JPG-копии» → запустить снова. [HEIC переехали в `_heic_originals/` с той же структурой папок, JPG остались; ничего не удалено.]
- [ ] «Найти и перенести в «_duplicates»». [Точные копии переехали в `_duplicates/`, оригиналы на месте; повторный запуск — «не найдено».]
- [ ] Выключить «Раскладывать по датам съёмки» → «Переложить уже скачанное». [Все файлы в одной папке, пустые папки по датам удалены; в режиме «Оба» JPG-копии переехали вместе с HEIC.] Включить обратно и переложить снова. [Снова по годам и месяцам.]
- [ ] Если папка с фото на флешке в FAT32: [в карточке «Папка для фото» предупреждение про файлы больше 4 ГБ]. Кнопка «Открыть папку» открывает проводник.

## Яндекс Диск

- [ ] «Яндекс Диск» → «Ввести ключ» → вставить токен → «Проверить и сохранить». [«Подключён: логин, свободно X из Y». Неверный токен — «Яндекс не принял ключ доступа — получите новый».]
- [ ] «Загрузить в Яндекс Диск». [Ход загрузки с числом файлов; на Диске появилась папка «iCloud БК» с теми же папками по годам.]
- [ ] Запустить загрузку второй раз. [Все файлы «пропущено» — они уже на Диске.]
- [ ] Заменить на Диске один файл другим с тем же именем (или положить туда чужой `IMG_0001.JPG`) и запустить снова. [Наш файл залит рядом под именем с хвостом `_abc123`, чужой не перезаписан.]
- [ ] Если на Диске мало места: [сообщение, сколько нужно и сколько свободно, ничего не залито].
- [ ] Ошибку 429 (лимит запросов) вручную не вызвать; поведение покрыто тестами с подменённым API: пауза на минуту и продолжение.

## Выход и безопасность

- [ ] «Помощь» → «Скачать отчёт для поддержки». [ZIP с `webui.log` и `support-info.json`; внутри нет токена, пароля, кода и полного Apple ID.]
- [ ] «Помощь» → «Выйти из Apple ID» → «Выйти». [Папка `session/` пуста, слева «Apple ID: не вошли», скачанные файлы на месте.]
- [ ] В iCloud на айфоне ничего не изменилось: число фото то же, «Недавно удалённые» пусты (программа ничего не удаляет и не меняет).

## Что сообщить, если что-то не так

Экран, что нажали, что ожидали и что увидели, плюс отчёт для поддержки из «Помощи». Для ошибок Apple полезна последняя строка `WARNING | webui.engine` из `logs/webui.log`.
