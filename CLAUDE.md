# iCloud БК — правила проекта

Локальное веб-приложение, которое в один клик скачивает всю медиатеку iCloud Фото на компьютер. Каркас и стиль взяты из «Яндекс БК» (https://github.com/PXSYS13/yadisk_backup, копия только для чтения лежит в `_reference/yadisk_backup`). Пользователи — не программисты: простота важнее гибкости, тексты интерфейса на русском.

## Принятые решения (не обсуждать заново)

1. **Каркас — «Яндекс БК».** Веб-интерфейс (FastAPI и `webui_assets`), `state.py` (SQLite-трекер и докачка), `dedupe.py`, `organize.py`, лаунчеры `webui.bat` и `webui.sh` перенесены и адаптированы оттуда. Сохраняем стиль кода, структуру и вид интерфейса: тёмная тема в стиле Apple, без эмодзи и визуального шума. Python и зависимости — как в «Яндекс БК» (uv, `pyproject.toml`, `uv.lock`), если icloudpd не требует новее.
2. **Движок — icloudpd (MIT).** Вход в iCloud и скачивание с нуля не пишем. Вся работа с icloudpd идёт через один модуль-адаптер `icloud_engine.py` с узким интерфейсом: войти, подтвердить код 2FA, получить список файлов, скачать файл. Если Apple или icloudpd что-то поменяют, правится только этот модуль. Точная версия icloudpd зафиксирована в `requirements.txt` и `pyproject.toml`.
3. **Способ подключения icloudpd** выбран по факту после чтения исходников актуальной версии; решение и причина записаны в `docs/DECISIONS.md`.
4. **Только чтение из iCloud.** Никогда ничего не удаляем и не меняем в iCloud. Не используем режимы icloudpd, которые удаляют файлы: `auto-delete`, `delete-after-download`, `keep-icloud-recent-days` и подобные. Это семейные фото людей; одна ошибка здесь — невосполнимая потеря.
5. **Всё локально.** Сервер слушает только `127.0.0.1`, никакой телеметрии и сторонних серверов. Пароль Apple ID не сохраняется; хранится только сессия в локальной папке `session/` (она в `.gitignore`), кнопка «Выйти» её удаляет. Пароли, коды 2FA и токены не попадают в логи и маскируются в интерфейсе.
6. **Защита не хуже «Яндекс БК»:** проверка Host и Origin (CSRF), проверка путей (нельзя выбрать корень диска, домашнюю или системную папку), атомарная запись файлов настроек и наших файлов сессии.

## Как работать

- Тексты интерфейса, журналы, комментарии и документация — на русском, простыми словами; кнопки называем действием.
- Поведение только для Windows закрываем проверкой `utils.IS_WINDOWS`; проверки путей должны проходить и на Windows, и на Linux.
- Тесты не трогают настоящие `.env`, `session/` и базы: `tests/conftest.py` подменяет пути в `webapp/paths.py`. Модули читают пути и настройки в момент вызова, а не при импорте.
- `.bat`-файлы хранятся с CRLF (`.gitattributes`), иначе cmd.exe путает метки.
- Уроки по ходу работы записываем в `docs/NOTES.md`: одна запись — одна строка с причиной.
- Фичи, абстракции и рефакторинг сверх брифа не добавляем; полезные идеи выносим в конец отчёта как предложения.

## Запуск

```bash
uv run webui.py            # http://127.0.0.1:8000
uv run webui.py --demo     # демо-движок без настоящего Apple ID
uv run pytest -q
uv run ruff check .
```
