# Для разработчиков

Спасибо, что хотите помочь. Здесь — как устроен проект, как его запустить из исходников и что проверить перед pull request.

## Окружение

Проект живёт на [uv](https://docs.astral.sh/uv/): он сам ставит нужный Python (3.10–3.13, в `.python-version` закреплён 3.12) и зависимости из `uv.lock`. `requirements.txt` — только для тех, кто ставит через pip.

```bash
uv sync                    # окружение с зависимостями для разработки (pytest, ruff, httpx)
uv run webui.py            # веб-интерфейс на http://127.0.0.1:8000
uv run webui.py --demo     # демо-движок без настоящего Apple ID: любой логин и пароль, код 123456
uv run pytest -q           # тесты
uv run ruff check .        # линтер
```

Полезные ключи и переменные окружения:

- `--no-browser` (или `ICLOUD_BK_NO_BROWSER=1`) — не открывать браузер при запуске;
- `ICLOUD_BK_PORT=8010` — другой порт; без него занятый 8000 программа сама меняет на следующий свободный;
- `ICLOUD_BK_DEMO=1` — то же, что `--demo`; `ICLOUD_BK_DEMO_SPEED=200000` — скорость демо-скачивания в байтах в секунду, чтобы дольше видеть прогресс.

В демо-режиме пароль `wrong` показывает ошибку входа, любой код, кроме `123456`, — ошибку кода. Демо держит свои файлы отдельно от настоящих: база `state_demo.db`, сессия `session_demo/`, папка `downloads_demo/`, медиатека `_demo_cloud/` (всё в `.gitignore`).

## Как устроен проект

```
webui.py              запуск веб-интерфейса: собирает приложение FastAPI из webapp/
webapp/               сервер интерфейса по разделам (список — в webapp/__init__.py):
  pipeline.py         рабочий поток: список медиатеки и скачивание с докачкой
  processing.py       задачи обработки: HEIC в JPG, дубли, раскладка, загрузка в Яндекс Диск
  account.py          вход в Apple ID, код 2FA, выход
  control.py          кнопки: папка, настройки, старт, пауза, обработка
  status.py           /api/status — всё, что опрашивает интерфейс
  ports.py            выбор порта и защита от чужих сайтов (Host, Origin)
  config.py, paths.py, runtime.py, logs.py, local_disk.py, pages.py
webui_assets/
  app.html            каркас интерфейса
  static/             app.css и js/: core.js, components.js, screens/*.js (без сборки)

icloud_engine.py      адаптер к icloudpd: единственное место, где программа говорит с iCloud
demo_engine.py        демо-движок с тем же интерфейсом, без Apple
state.py              SQLite-состояние медиатеки и скачивания (state.db)
heic_convert.py       JPG-копии из HEIC с сохранением EXIF
dedupe.py             одинаковые файлы по MD5 — в _duplicates
organize.py           раскладка по годам и месяцам
yandex_upload.py      копия на Яндекс Диск
utils.py              общие утилиты: пути, маскирование секретов, пределы

tests/                pytest
docs/
  DECISIONS.md        почему icloudpd подключён как библиотека и другие решения
  NOTES.md            уроки по ходу работы: одна запись — одна строка с причиной
  MANUAL_TEST.md      чек-лист ручной проверки на настоящем Apple ID
  screenshots/        скриншоты для README
```

Работа с iCloud идёт только через `icloud_engine.py` (узкий интерфейс `Engine`: войти, подтвердить код, список файлов, поток скачивания). Если Apple или icloudpd что-то поменяют, правится только этот модуль. Скачивание и обработка идут в фоновых потоках того же процесса, а не отдельными процессами: сессия Apple живёт в памяти после ввода кода. Подробности и причины — в `docs/DECISIONS.md`.

## Правила

- **Только чтение из iCloud.** Программа ничего не удаляет и не меняет в iCloud. Режимы icloudpd, которые удаляют файлы (`auto-delete`, `delete-after-download`, `keep-icloud-recent-days` и подобные), не используются и не должны появиться. Это семейные фото людей; одна ошибка здесь — невосполнимая потеря.
- **Всё локально.** Сервер слушает только `127.0.0.1`, никакой телеметрии и сторонних серверов. Пароль Apple ID не сохраняется; пароли, коды 2FA и ключи доступа не попадают в журналы и маскируются в интерфейсе (`utils.mask_token`).
- Тексты интерфейса, журналы, комментарии и документация — на русском. Пользователи программы — не программисты: пишите простыми словами, кнопки называйте действием («Выйти из Apple ID», а не «Изменить»).
- Поведение только для Windows закрывайте проверкой `utils.IS_WINDOWS`; проверки путей должны проходить и на Windows, и на Linux.
- Файлы открывайте с `encoding="utf-8"`, в том числе через `subprocess.run(..., text=True)`: в CI включён `PYTHONWARNDEFAULTENCODING=1`, и предупреждение считается ошибкой, а у GitHub Actions на Windows кодировка по умолчанию cp1252.
- Тесты не трогают настоящие `.env`, `session/` и базы: `tests/conftest.py` подменяет пути в `webapp/paths.py` на временные. Новые файлы проекта добавляйте туда же. Модули читают пути и настройки в момент вызова (`paths.DB_FILE`, `config.get_config()`), а не копируют при импорте, иначе подмена в тестах до них не дойдёт.
- После правок интерфейса поднимите `APP_VERSION` в `utils.py`: версия в адресах статики — единственный способ сбросить кеш браузера.
- `.bat`-файлы хранятся с окончаниями строк CRLF (`.gitattributes`), иначе cmd.exe путает метки.
- Уроки по ходу работы записывайте в `docs/NOTES.md`: одна запись — одна строка с причиной.

## Обновление icloudpd

Версия icloudpd зафиксирована в `pyproject.toml` и `requirements.txt` прямой ссылкой на чистый Python-wheel `py3-none-any` (платформенные wheel на PyPI — бинарники PyInstaller, их нельзя импортировать). Чтобы обновить: замените ссылку и хеш sha256 в обоих файлах, выполните `uv lock`, прогоните тесты и пройдите `docs/MANUAL_TEST.md` на настоящем Apple ID — вход и список файлов проверяются только там.

## Pull request

1. `uv run ruff check .` и `uv run pytest -q` проходят.
2. Если менялся интерфейс — приложите скриншот (подойдёт демо-режим) в тёмной и светлой теме.
3. Опишите, что меняется для пользователя, простыми словами.

CI (`.github/workflows/ci.yml`) запускает линтер и тесты на Windows, Linux и macOS с Python 3.10 и 3.13.
